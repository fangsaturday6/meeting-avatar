## 阶段一：底座（必须先做，单独上线）

目标：每场会结束后，`workspace/audio/<会议编号>/` 里有完整的原始音频、每句话的位置和声纹；崩溃不丢；能用一条命令把这场会重放一遍。

### 1. 采集帧带序号，后台记音频时钟

- `audio.js`：每个二进制帧前加 8 字节头（4 字节帧序号 + 4 字节本帧采样数，小端）。
- `api.ws_audio`：解析头部，帧序号跳号就记一次丢帧；**按收到的采样数推进「音频时钟」**（采样数计，不用墙钟），丢掉的帧用零补齐，保证音频时钟和会议时间对得上。
- 兼容：没有头的旧帧（长度为奇数个采样或标志位）照旧处理，演示后台和 `test_api` 不用一起改。
- 文件：`avatar/web/audio.js`、`avatar/web/pcm-worklet.js`、`avatar/api.py`（拆出 `AudioIn` 类负责解帧和时钟，`ws_audio` 只转发）。

### 2. Recorder：分块落盘

- 新文件 `avatar/recorder.py`，一个 `Recorder` 对应一路声音（先只有 `mic`，阶段 B 加 `system`、`self`）。
- 格式：16 kHz 单声道 16 位 WAV，标准库 `wave` 写，不加依赖。每 60 秒一块：`mic-0000.wav`、`mic-0001.wav`…。先写 `.part`，`fsync` 后改名（学 Anarlog），崩溃最多丢最后一块的未落盘部分。
- 写盘放线程，不进事件循环；磁盘写失败不影响开会，只置健康状态。
- 体积：约 115 MB/小时。
- 保留策略：新设置项 `keep_audio`，取值 `never / until_polished / always`，走 `Meeting.change_settings`，设置窗口加一项（稳定 id：`set-keep-audio`），接口表同步。**默认值待定（见文末）**。
- 目录权限 700（学拾音）。

### 3. 每句话对得回音频

- `Line` 新增 `at: float`（这句话在音频时钟上的起点，秒）和 `source: str`（`mic` / `system` / `typed` / `bot`）。sherpa-onnx VAD 的 `front.start` 是采样下标，换算即可；`Ears.reset` 时清零时钟。
- `Ears.on_utterance` 多传 `at`；`floor` 写 `Line` 时带上。
- 会议记录：`archive.py` 在文件头写 YAML frontmatter（编号、开始时间、时长、音频是否保留、说话人名单），「## 对话」每段带一个不显眼的锚点 `<a id="L123"></a>`，供纪要回链和 MCP 定位。`_meta` 改为优先读 frontmatter，旧文件照旧解析。

### 4. 声纹留存

- `voices.jsonl`：每句一行 `{line_id, at, seconds, speaker_id, emb}`（`emb` 为 base64 的 float32），追加写，崩溃安全。
- `SpeakerBook` 不改逻辑，只是 `floor` 在归属后把结果交给 Recorder 记一笔。

### 5. 采集健康

- 新文件 `avatar/health.py`：吃 `AudioIn` 的统计，5 秒窗口算三件事——全零比例、丢帧比例、电平过低时长。输出 `mic.health = ok | silent | dropping | quiet | denied`（`denied` 来自前端 `getUserMedia` 报错）。
- 状态走 `Meeting.set_flag` → 快照和事件里有，`GET /api/state` 就能读到（Agent 不读页面也知道）。
- 主窗口：不加文字，用形象表达——听不清时做「侧耳 / 敲麦克风」类动作。需要在 `tools/figure_hunyuan.py` 的 `CLIPS` 加一个动作并重新导出，备用形象在 `character.js` 的 `POSES` 加一个姿势。颜色不占用青紫琥珀橙红。
- 设置窗口里的麦克风一栏显示健康状态和一句人话（「一直收到的是静音，看看麦克风是不是被关了」），不出现原始报错。
- 顺带：会议结束时确认两个 `AudioContext` 都关闭（报告提到 Electron 下不关会让电脑不休眠）。

### 6. 评测台 `tools/replay.py`

- `uv run python -m tools.replay <会议编号> [--set lead_in=0.3 --set min_silence=0.6 ...]`：把存档音频按实时节奏（或加速）喂给**真实的 `Ears`**，输出逐句结果、说话人归属、识别耗时。
- `--compare 配置A 配置B`：两套参数的逐句差异；有人工校对稿（`workspace/eval/<编号>.ref.md`）时算字错率和说话人错配率。
- 这是后面所有「标了推断 / 未核实」条目的裁判。CLAUDE.md 里「调断句或识别参数后用真实 Ears 喂一段音频看」的约定，从此有了固定工具。

### 验收

- 开一场 10 分钟的会，中途杀掉后台进程再起：音频最多缺最后一分钟，记录完整。
- `replay` 重放同一场会，得到的句子数和原记录相差在 ±5% 内（识别本身有随机性的部分除外）。
- 拔麦克风、系统静音键、拒绝权限三种情况，`mic.health` 分别给出对应状态，形象有反应。
- `uv run pytest` 通过；浅色、深色、窄屏看一眼设置窗口。

## 主线 A：会后重算与说话人修正（依赖阶段一）

报告第 2、3、9、11 条，外加第 13 条的开关。

### A1. 散会后全场重聚类，回填记录

- 新文件 `avatar/recluster.py`，纯函数：输入每句声纹、时长、已锁定的说话人，输出新的归属。做法：只用 ≥2 秒的句子做层次聚类（余弦，阈值用评测台标定），短句按最近质心归入；新簇与会中编号用质心一对一匹配，**用户改过名的说话人锁定不动**（学 OpenWhispr）。
- 时机：`Hub` 散会流程里，在出纪要之前、`Meeting` 对象还在内存时跑，改 `Line.speaker_id` 后重存记录，再出纪要和整理稿。
- 记录里标一笔「说话人已在会后重新核对」；`meeting.log` 记下改了几句、从谁改成谁。

### A2. 在线归簇的小修（用评测台标定，不照搬别家阈值）

`SpeakerBook.assign` 里补：更新质心用比归属更严的阈值；每人保留最多 10 份样例、匹配取最大；最佳和次佳差距 < 0.05 时不硬判（沿用上一位或记「有人」）；新说话人试用期（攒够 2 次、合计 4 秒才转正，否则并回最近的人）；每 N 句检查一次可合并的簇对；可选人数上限（设置项，留空不限）。每一条都要在评测台上证明不变差才留。

### A3. 改判、合并、锁定

- 接口：`POST /api/speakers/merge`（把 B 并进 A）、`POST /api/lines/{id}/speaker`（单句改判）、已有的改名接口加 `locked`。只改映射，不重跑识别（学听记）。
- 设置窗口的说话人一栏：每位说话人旁边带一句他说过的原话（学 Speakr），拖一位到另一位上就是合并。稳定 id 补进 `tests/test_pages.py`。
- 会后重聚类、在线归簇都不碰锁定的说话人。

### A4. 纪要回链

- 纪要提示词要求每条结论和待办带上来源段落的锚点（`[见原话](#L123)`），`checked_polish` 式校验：锚点必须存在于本场记录，否则去掉链接、保留文字。
- 待办的负责人优先从已认出的说话人里选（推断做法，先只做建议）。

### A5. 会后同模型重识别（实验开关，默认关）

把同一说话人相邻的碎句合并到约 15 秒，用同一个 SenseVoice 重识别，在评测台上和实时结果比字错率；只有明显变好才打开，并且排在 `slow_brain.polish` 之前。

## 主线 B：系统声音单独一路（依赖阶段一的多路 Recorder，可与 A 并行）

报告第 12 条。未核实项最多，所以**先做一次验证，再决定做不做**。

### B0. 验证（半天，结论写进本文件）

在 Electron 43 上实测：`setDisplayMediaRequestHandler` 回 `audio: 'loopback'` 能不能只要音频、不弹屏幕录制权限；`NSAudioCaptureUsageDescription` 加上后权限弹窗长什么样、多久重新确认；数字人自己的 TTS 会不会被采进系统声音那一路；`SystemLoopbackAsAecReference` 带来的 170 ms 采集延迟在本机是否存在。任何一项不过关，就退回「保留虚拟声卡方案、只做下面的分路识别」。

### B1. 分路

- `app/main.js` 注册回环；`app/pack.js` 加权限说明；`audio.js` 线上会议模式额外开一路系统声音，同样的帧格式，帧头加一个声道号。
- 后台：每路一个 `Ears` 和一个 `Recorder`，按音频时钟在事件层合并成同一条对话。
- 系统声音这一路的句子 `source=system`，说话人只在这一路内部聚类；麦克风一路只剩房间里的人，不再被线上声音污染。
- 健康探测对系统声音同样适用：开着线上会议却一直全零，形象给出反应，设置窗口说清是缺权限。
- 现有虚拟声卡方案保留为后备，设置里不新增选项（自动选能用的那条）。

## 主线 D：接话打断与对外接口（大部分不依赖底座，可随时插入）

### D1. 接话与打断（`floor.py`）

报告第 7、17 条及第五章的几条：

- 误打断续说推广到所有「被打断后没识别出字」的情况（现在只覆盖回声）。
- 打断判定加「识别出实词」条件，「嗯」「对」不算。
- 每位说话人一个句间停顿的滑动平均，替代全局 `min_silence` 判断「说完没」（LiveKit 动态断句的思路，本项目有声纹可以按人做）。
- 欠着的汇报：空闲满 N 秒才说、有人开口就重新计时。
- Smart Turn v3 作为「可以提前开始想」的附加信号——中文准确率偏低、多人场景无数据，放在最后，先在评测台上看它在本项目录音里的表现。
- 每项都先补 `tests/test_floor.py` 的场景，再跑 `uv run python -m tests.scenarios`。

### D2. MCP 与接口（`mcp_server.py`、`api.py`）

- `read_meeting` 补游标（`since_line`）和 `next` / `complete`，单次上限 200 段。
- 新增 `read_live`：会中按游标读最新的话（学 Minutes / joinly）。
- 会议敏感标记：frontmatter 加 `sensitivity`，`guarded` 场次或用户标记的敏感会议，`list/search` 默认排除，`read` 只返回无正文的桩。
- 暂不开放写入工具；以后要开，只允许追加署名批注，不许改说话人和正文。
- README 接口表同步。

### D3. 告知与隐私

- 开场白里由数字人自己说一句「这场会我会记录」（角色行为，不弹窗）——**要不要说、怎么说待定**。
- 会中「这段别记」语音指令：之后到「可以记了」之间的话不进记录、不落音频。
- 设置窗口列明：音频不出本机；哪些文字会发给哪个模型。
- 跨会议声纹库（报告第 18 条）放到最后，单独立项：涉及生物特征，先定 `guarded` 下的规则再做。

## 待拍板

1. **音频默认留多久**：建议「我在场」时默认一直留（评测台要用），「替我开会」（`guarded`）时默认整理稿出完就删音频、只留文字和声纹。
2. **开场要不要主动说「我会记录」**。
3. **评测用的校对稿**：主线 C 要比字错率和说话人错配，需要你挑 2–3 场会、把对话校对一遍（改错字、改说话人），每场大约半小时。不校对也能做，只是只能比「差异」不能比「对错」。
