# 接给我的智能体

2026-11-12。让用户在产品里把会议记录（纪要、整理稿、逐句对话）接给自己的智能体，之前只能在终端跑 `avatar.connect`。

## 范围

用户确认的三类智能体都在本机：Claude Code / Codex、本机其他 MCP 客户端（Cursor、Claude 桌面版等）、自己写的程序。
云端平台（够不到这台电脑）不做，所以没有对外地址和访问口令。

## 界面

设置窗口「设置」页最下面一组「接给我的智能体」，一行一个，不放说明文字：

| 行 | 控件 | id |
|---|---|---|
| Claude Code | 开关，打开就接上，再点取消 | `agent-claude` |
| Codex | 同上；没装时不给开关，写「这台电脑上没装」 | `agent-codex` |
| 其他智能体 | 按钮「复制一段话发给它」，点完变成「已复制，粘贴给它」 | `btn-copy-agent-guide` |

报错在这一组下面（`agents-error`），一句人话。开关用黑白灰，不占用四个状态色。

第一版是两个开关加「复制 MCP 配置」「复制 MCP 地址」两个按钮，用户看不出复制完要干什么，作废。
改成复制一段写给智能体看的话：用户只管粘贴，怎么接由智能体自己照着做，下一步写在按钮上。

## 后台

- `connect.py`：`status(id)` 查一个客户端的状态（`on` / `off` / `missing` / `taken` / `unknown`），
  `set_connected(id, connected)` 接上或取消，`guide(base_url)` 生成接入说明，`Connector` 是接口层用的那一面。
  原则不变：那边有同名的别的服务、或者没能确认现有配置时不动它。
- `GET /api/agents`、`PUT /api/agents/{id}`：查状态、接上或取消。查状态要起子进程，放线程里。
- `POST /mcp`：HTTP 方式的 MCP，复用 `mcp_server.py` 的处理函数，一问一答回 JSON，不做服务端推送。
  带外站 `Origin` 的请求回 403（防止网页偷读，包括把域名指到 127.0.0.1 的做法）。
- `Hub(agents=...)` 可以换成假的登记器；测试和演示后台都用假的，不碰真实配置。

## 不做

- MCP 工具保持只读。重新整理纪要走现有的 `POST /api/meetings/{id}/minutes`。
- 不在界面上显示或切换大模型。
- 登记状态不进 `/api/state`：查一次要一两秒，由设置窗口单独取，改动后发 `agents` 事件。
