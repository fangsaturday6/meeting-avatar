## 一、目前最活跃、口碑最好的开源项目有哪些（逐个清单）

### Takeaway
2026 年这个品类已经非常拥挤：头部是 Meetily（3.2 万 star，但说话人、模板、MCP 全锁在付费版）和 Anarlog（原 Hyprnote，9.9k，MIT），增长最快、设计最值得抄的反而是一批 2026 年新出的小而精项目——Minutes（把会议做成 Agent 可查的 Markdown 记忆层，34 个 MCP 工具）、Muesli、OpenOats、Yogurt、Humla、StenoAI，以及中文向的知了 Cicada、Tingo、拾音 Shiyin、JustSaid。原清单里有几项已变样：Hyprnote 两次改名、Whishper 改名 anysub 且转做字幕、screenpipe 和 Natively 转为「源码可见」非开源、Pluely 和 Glass 仓库已 404、Amical 的会议功能尚未发布。

#### A. 桌面会议笔记（无机器人入会，本机采音）

**1. Meetily**（原仓库名 meeting-minutes）
- 仓库已改名为 `Zackriya-Solutions/meetily`；32,655 star；最近推送 2026-11-12；最新发布 v0.4.1（2026-09-12，README 徽章仍标 Pre-Release）；MIT；Rust（Tauri）+ Next.js 前端。— [GitHub](https://github.com/Zackriya-Solutions/meetily)
- 采音：麦克风 + 系统声音同时采，README 称带「intelligent ducking and clipping prevention」。macOS 端源码 `audio/capture/core_audio.rs` 用的是 Core Audio **process tap + aggregate device**（全局单声道 tap，创建 tap 时自动弹权限框，被拒则得到全零静音）。— [README](https://github.com/Zackriya-Solutions/meetily)；[core_audio.rs](https://github.com/Zackriya-Solutions/meetily/blob/main/frontend/src-tauri/src/audio/capture/core_audio.rs)
- 转写：实时出字（Whisper via whisper.cpp、Parakeet tdt-0.6b-v3 ONNX，全本机）；另有「Import & Enhance（Beta）」可导入音频或换模型/语言重转已录会议。— [README](https://github.com/Zackriya-Solutions/meetily)
- 社区版 vs 付费版：社区版只有本机转写 + AI 摘要（Ollama 或云端）；**说话人识别、自定义摘要模板、PDF/DOCX 导出、自动检测会议、MCP/CLI/webhook 全部是 Pro**（$10/人/月，年付）；「Chat with Meetings」「日历」标为 Coming Soon。— [README](https://github.com/Zackriya-Solutions/meetily)
- 崩溃恢复：源码 `incremental_saver.rs` 每 30 秒把缓冲写成一个 checkpoint 文件到会议目录的 `.checkpoints/`，结束时用 FFmpeg concat 合并成 `audio.mp4` 再清理；注释写明目的是「minimize memory usage and enable crash recovery」，且只存混音后的单轨。— [incremental_saver.rs](https://github.com/Zackriya-Solutions/meetily/blob/main/frontend/src-tauri/src/audio/incremental_saver.rs)
- 用户呼声（按 reactions 排序的 issue）：Linux 支持 #32、摘要多语言 #233、识别说话人 #226/#230、摘要模板可配置 #243、多轨音频 #241、自动检测会议 #218、深色模式 #411、领域词表提示 #474、社区版不能改录音目录 #376。— [issues](https://github.com/Zackriya-Solutions/meetily/issues?q=is%3Aissue+sort%3Areactions-%2B1-desc)
- 说话人 issue #230（2025-10-30 开，至 2026-10-28 仍开着）：用户抱怨「Why is this feature only available in Pro?」「this should be a very basic one」；协作者称试过 pyannote-rs 准确度不满意；2026-10-08 有社区 PR #833 给社区版加本机说话人识别（beta 开关）。— [issue #230](https://github.com/Zackriya-Solutions/meetily/issues/230)
- 中文：README 未列支持语言，只提到重转时可选语言。— [README](https://github.com/Zackriya-Solutions/meetily)

**2. Anarlog**（原 Hyprnote → Char → Anarlog）
- `fastrepl/hyprnote` 现 301 跳转到 `fastrepl/anarlog`；9,875 star；最近推送 2026-11-10；最新发布 desktop_v1.4.34（2026-10-29）；MIT；Tauri v2 + React/TS + Rust。— [GitHub](https://github.com/fastrepl/anarlog)
- 改名史：2026-02 中旬 Hyprnote 改名 Char；2026-05-03 官方博文宣布会议笔记这条线拆出来叫 Anarlog（「granola」的字母重排），Char 留给团队另一个「智能待办」产品；同时许可证从 GPL 改为 MIT；2026-08 更新称迁移完成，macOS 最成熟，Windows/Linux 为 beta。— [char-is-now-anarlog](https://anarlog.so/blog/char-is-now-anarlog)；[hyprnote-is-now-char](https://char.com/blog/hyprnote-is-now-char)
- 形态：Granola 式——会中自己记，会后 AI 结合「Transcript + memo」生成笔记，可像文档一样编辑、导出 Markdown；数据在「本地 SQLite + 本地文件」，录音是普通本地文件。— [README](https://github.com/fastrepl/anarlog)
- 识别：付费云端走 Soniox 5（实时 + 批量）；本机用 Apple Speech 等或自带 key。官网称支持 45+ 语言。— [README](https://github.com/fastrepl/anarlog)；[博文](https://anarlog.so/blog/char-is-now-anarlog)
- Agent 接口：仓库含 `apps/cli`（「Local CLI and MCP server」）和 `skills/anarlog`（已发布的 agent skill）；官网价目表把「local API、CLI、MCP、webhooks」列在免费档。— [README](https://github.com/fastrepl/anarlog)；[官网](https://anarlog.so/)
- 价格与分层：Free $0（本机转写不限量、BYOK、模板、文件夹、聊天、导出，说话人为**手动标注**）；Pro $14/人/月（云端转写/LLM、「更好的说话人识别」、同步、分享、全局听写）；官网称「共享屏幕时保持隐藏」。— [官网](https://anarlog.so/)
- HN 口碑（Launch HN，2025-07-29，270 分 / 180 评论）：称赞本地优先、无机器人、免注册、Obsidian 导出；批评集中在**没有说话人区分是 dealbreaker**（官网当时宣称了尚未做完的功能）、「数据不出本机」却带 Sentry/PostHog、官网客户 logo 误导、GPL 妨碍公司内使用、想要 Markdown 而不是 SQLite、启动时自带背景音乐。— [HN 44725306](https://news.ycombinator.com/item?id=44725306)

**3. Minutes**
- `silverstein/minutes`；1,598 star；最近推送 2026-11-12；v0.33.1（2026-11-11）；MIT；Rust 核心 + Tauri 菜单栏应用，MCP 服务器是 npm 包 `minutes-mcp`，CLI 在 crates.io。— [GitHub](https://github.com/silverstein/minutes)
- 定位：「给你已经在用的 AI 的对话记忆」——会议、通话、语音备忘、听写在本机转写后写成 `~/meetings/` 下带 YAML frontmatter 的 Markdown（字段含 `title/type/date/duration/context/action_items[assignee,task,due,status]/decisions`），Claude Code / Codex / Cursor 直接查。— [README](https://github.com/silverstein/minutes)
- 采音：桌面应用在 macOS 15+ 用 ScreenCaptureKit 采麦克风 + 通话声音（需屏幕录制和麦克风权限）；纯 CLI 采系统声音要 BlackHole + 多输出设备。— [features.md](https://github.com/silverstein/minutes/blob/main/docs/features.md)
- 转写：默认会后（`minutes record` → `minutes stop` 后转写）；另有 `minutes live` 实时流，「定稿行才是持久记录，最多一条临时草稿，3 秒过期，永不写入文件/事件历史/日志」。引擎 Whisper（本机）、Parakeet v3（Apple Silicon 听写默认）。— [features.md](https://github.com/silverstein/minutes/blob/main/docs/features.md)
- 自动录通话（macOS，默认关）：只有当**麦克风活动归属到通话应用的进程族**（Zoom、Teams 桌面版）才触发；每通电话只自动尝试一次；录音条上写明应用名和「自动开始」；通话结束后弹 30 秒倒计时可点「Keep recording」；浏览器里的会议一律手动；配置了「需确认同意」时不自动开始；采不到系统声音时**不会**退化成只录麦克风。— [call-auto-record.md](https://github.com/silverstein/minutes/blob/main/docs/call-auto-record.md)
- 恢复：原生采集有看门狗——两路都 30 秒没写入就告警，2 分钟无进展且独立检查确认两个 stem 文件都不再增长才走正常收尾，已采音频保留；麦克风和系统声音分存为 `call.voice.wav` / `call.system.wav` 两个 stem；`minutes recover-stem` 能把超 4GB / 未收尾的 WAV 按小时切片恢复并写 `recovery.json`（含每片的帧偏移和 SHA256），不动原件。— [native-capture-recovery.md](https://github.com/silverstein/minutes/blob/main/docs/native-capture-recovery.md)
- 其他：⌘⇧K 命令面板；`minutes sensitive start/stop` 敏感会议模式（不录音，只存带时间的手打标记，保存为 `capture: none` / `sensitivity: restricted`）；CLI 有 `search / actions / person / people / commitments / consistency / research`。— [features.md](https://github.com/silverstein/minutes/blob/main/docs/features.md)
- 中文：未声明；`--language` 收 ISO 639-1 代码。— [features.md](https://github.com/silverstein/minutes/blob/main/docs/features.md)

**7. Humla**
- `michaelwilhelmsen/humla`；345 star；v0.75.0（2026-11-10）；MIT；Tauri 2 + Rust + React 19（Tiptap 编辑器），Swift sidecar 负责采音和说话人。— [GitHub](https://github.com/michaelwilhelmsen/humla)
- 采音：Swift helper 用 AVAudioEngine + ScreenCaptureKit 把麦克风和系统声音录成**两条独立流**；按停顿切片边录边送识别；说话人区分在**停止后离线跑**，标 Speaker 1/2…，点标签改名即全文替换；默认模型最多 8 人，超过用 pyannote 聚类并可在笔记上填人数。— [README](https://github.com/michaelwilhelmsen/humla)
- 音频保留：**默认转写和说话人识别做完就删音频**（所以默认没有回放）；勾「Keep recorded audio」才存混音 `playback.wav` + 分源 WAV（约 1MB/分钟/声道），另有「Delete stored audio」只清音频留转写。— [README](https://github.com/michaelwilhelmsen/humla)
- 会后：Summarize 把你的笔记 + 转写交给 LLM，预设模板 Meeting / 1:1 / Lecture / Interview / Brainstorm / Voice memo；Chat 标签是「agentic 检索」（FTS5 关键词 + 向量），引用的笔记显示为可点的小标签，范围可选单条 / 文件夹 / 全部。— [README](https://github.com/michaelwilhelmsen/humla)
- MCP：自带 stdio 服务器 `humla-mcp`，6 个只读工具 `search_notes / get_note / get_transcript / list_notes / list_folders / list_clients`，默认关，设置页给 Claude Code / Codex 的配置片段。— [README](https://github.com/michaelwilhelmsen/humla)

**8. StenoAI（StenographAI）**

- 检测与同意：检测到会议先提议记笔记，结束时提议出摘要；自动录音默认关，开了会发带 Stop 的通知，文档提醒按当地要求取得同意；`stenoai://record/start|stop` 深链可接「快捷指令」；全局快捷键 ⌘⇧R。— [README](https://github.com/stenolabs/stenoai)
- 会后：摘要和转写存 Markdown；自定义报告模板，一条笔记可挂多份报告；「Ask your meetings」可选范围（本场 / 全部 / 文件夹）；提供只读的 `steno` agent skill 和 `granola-to-steno` 导入 skill，无内置 MCP。— [README](https://github.com/stenolabs/stenoai)

## 二、「录音中」界面的取舍，以及用户称赞和吐槽

### Takeaway
录音中界面大致分四派：**笔记编辑器为主**（Granola 派：Anarlog、Humla）、**转写 + 笔记左右并排**（拾音、Note67、StenoAI）、**极简指示器**（Muesli 的刘海/悬浮点、Minutes 的菜单栏 + 录音条、StenoAI 的转写药丸、知了的「有人说话才出现」字幕条）、**会中主动提示**（OpenOats、call.md、JustSaid、Cluely 类）。用户最一致的吐槽是「没有说话人区分」和「同意/告知」，最一致的称赞是无机器人、免注册、回声和幻觉处理到位。

### Cited Findings
- 笔记编辑器派：Humla 录音时界面是 Tiptap 自由笔记编辑器，笔记随转写一起连续保存；Anarlog 会后用「Transcript + memo」生成笔记。— [Humla](https://github.com/michaelwilhelmsen/humla)；[Anarlog](https://github.com/fastrepl/anarlog)
- 并排派：拾音「左实时转写、右我的笔记、带时间戳」，另有分源电平表和试音；Note67 实时转写行出现在之前的录音下方并保持可见，笔记边打边存。— [拾音](https://github.com/juinwei7/Shiyin)；[Note67](https://github.com/ZapYap-com/note67)
- 极简指示器派：Muesli 进度显示「在刘海或悬浮指示器」；StenoAI 是贴在应用旁的紧凑转写药丸 + 聊天气泡视图；Minutes 是菜单栏应用 + 录音条（自动开始时写明应用名和「自动开始」）+ ⌘⇧K 命令面板；知了字幕条只在有人说话时出现、鼠标悬停变透明。— [Muesli](https://github.com/Muesli-HQ/muesli)；[StenoAI](https://github.com/stenolabs/stenoai)；[Minutes](https://github.com/silverstein/minutes/blob/main/docs/call-auto-record.md)；[知了](https://github.com/wquguru/cicada)
- 会中主动提示派：OpenOats 对方说到实质内容时从你的笔记库里捞要点，有 90 秒冷却和相关度/新颖度门槛；call.md 显示发言占比、语速、独白检测并限频提醒；JustSaid 有人叫你名字时悬浮窗提醒、显示当前话题、把讨论实时整理成按话题的文档。— [OpenOats](https://github.com/yazinsai/OpenOats)；[call.md](https://github.com/video-db/call.md)；[JustSaid](https://github.com/bigbobro/JustSaid-public)
- 录音中可做的小动作：打书签/标记关键时刻（Tingo、拾音 ⌘B、call.md、JustSaid）；暂停/继续（Note67、拾音）；把一段标为「闲聊」不进纪要（JustSaid）；录音中直接提问（StenoAI）；调「预计人数」和「本场关闭说话人识别」（OpenWhispr）；录音前或录音中切语言（Yogurt 的笔记页脚语言菜单）。— [Tingo](https://github.com/tancheng33/tingo)；[拾音](https://github.com/juinwei7/Shiyin)；[JustSaid](https://github.com/bigbobro/JustSaid-public)；[StenoAI](https://github.com/stenolabs/stenoai)；[OpenWhispr](https://docs.openwhispr.com/help/meetings/speaker-labels.md)；[Yogurt](https://github.com/FrigadeHQ/yogurt)
- 屏幕共享时隐藏自己：OpenOats 窗口「默认对屏幕共享隐藏」，知了 Mac 笔记窗口共享时不可见，Anarlog 官网称共享屏幕时保持隐藏。— [OpenOats](https://github.com/yazinsai/OpenOats)；[知了](https://github.com/wquguru/cicada)；[Anarlog](https://anarlog.so/)
- 会议开始/结束检测的几种做法：
  - 麦克风活动归属到通话应用进程（Minutes）；看哪些应用在用麦克风 + 浏览器标签标题 + 日历事件（Yogurt）；持续麦克风活动 + 日历，应用在运行只作上下文（OpenWhispr）；日历 + 可选的摄像头/麦克风活动（Muesli）。— [Minutes](https://github.com/silverstein/minutes/blob/main/docs/call-auto-record.md)；[Yogurt](https://github.com/FrigadeHQ/yogurt)；[OpenWhispr](https://docs.openwhispr.com/help/meetings/how-meeting-detection-works.md)；[Muesli](https://github.com/Muesli-HQ/muesli)
  - 几乎全部是「**提议，不自动录**」：Yogurt 你同意才开始；拾音「从不自动录，并提醒你停止」；StenoAI 和 Minutes 的自动录音默认关；Note67 每通电话只提示一次。— [Yogurt](https://github.com/FrigadeHQ/yogurt)；[拾音](https://github.com/juinwei7/Shiyin)；[StenoAI](https://github.com/stenolabs/stenoai)；[Note67](https://github.com/ZapYap-com/note67)
  - 结束：Yogurt 通话结束自动停；Tingo 会议应用退出或静音超时（默认 10 分钟）自动停；Minutes 通话结束后 30 秒倒计时并给「Keep recording」，文档自己承认「长时间静音可能看起来像通话结束」；call.md 录满 2 小时自动停。— [Yogurt](https://github.com/FrigadeHQ/yogurt)；[Tingo](https://github.com/tancheng33/tingo)；[Minutes](https://github.com/silverstein/minutes/blob/main/docs/call-auto-record.md)；[call.md](https://github.com/video-db/call.md)
- 改说话人名字的做法：点标签改名全文替换（Humla、OpenWhispr）；日历参会人当候选 + 「Known speakers」跨会议沿用（OpenWhispr）；合并说话人、单句改派、拆出新说话人且不重跑识别（听记、拾音）；AI 从称呼/自我介绍猜名并附证据，用户接受才生效（Tingo、JustSaid）；读会议软件的「当前发言人」界面直接拿真名（Yogurt）。— [Humla](https://github.com/michaelwilhelmsen/humla)；[OpenWhispr](https://docs.openwhispr.com/help/meetings/speaker-labels.md)；[听记](https://github.com/baigong-ai/Tingji)；[拾音](https://github.com/juinwei7/Shiyin)；[Tingo](https://github.com/tancheng33/tingo)；[JustSaid](https://github.com/bigbobro/JustSaid-public)；[Yogurt](https://github.com/FrigadeHQ/yogurt)
- 用户称赞（HN）：本地优先、无机器人、免注册（Hyprnote 帖）；跨平台、回声检测、过滤 Whisper 静音幻觉、对「双方同意」州是「第一个合适的实现」（Yogurt 帖）；「第一个感觉打磨到位的本地工具」（Muesli 帖）。— [HN 44725306](https://news.ycombinator.com/item?id=44725306)；[HN 50454625](https://news.ycombinator.com/item?id=50454625)；[HN 48011116](https://news.ycombinator.com/item?id=48011116)
- 用户吐槽：没有说话人区分是 dealbreaker，尤其多人共用一个麦的混合会议（Hyprnote 帖多人）；说话人被锁进付费版（Meetily #230）；自称「数据不出本机」却带遥测（Hyprnote 帖）；Electron 占内存、想自己选模型、要「新人入会时提醒录音同意」（Yogurt 帖）；想要 Markdown 文件而不是 SQLite（Hyprnote、Muesli 帖）；实时转写延迟（Hyprnote 帖）；启动自带背景音乐（Hyprnote 帖）。— [HN 44725306](https://news.ycombinator.com/item?id=44725306)；[Meetily #230](https://github.com/Zackriya-Solutions/meetily/issues/230)；[HN 50454625](https://news.ycombinator.com/item?id=50454625)；[HN 48011116](https://news.ycombinator.com/item?id=48011116)

### Inferences
- 委托方「主窗口只放数字人本人、不加文字和按钮」的原则，与极简指示器派一致；可借鉴的不是往主窗口加东西，而是：(a) 提示只在需要时出现（知了字幕条、OpenWhispr 的合并提示与冷却期）；(b) 会议开始/结束用「提议 + 倒计时可撤销」而不是静默自动（Minutes 的 30 秒 Keep recording）；(c) 把「打点 / 这段别记」做成快捷键或一句话指令（委托方的数字人能听懂话，「这段别记」天然可以用语音实现）。
- 「预计人数」提示对在线聚类特别有用：OpenWhispr 文档明说人数设太高会把一个人拆成几个；委托方的声纹在线聚类可以加一个同样的软约束，并在设置窗口（`panel.*`）里给步进器。
- 起名流程里「AI 猜名 + 附原话证据 + 用户确认才生效」（Tingo、JustSaid）以及「拿不准的人名/术语列为待确认」（拾音）与委托方「改字必须过校验」的思路一致，可直接套到说话人改名和整理稿上。
- 用户对「说话人」的期望是基础功能而非增值功能；委托方已有声纹认人，这是相对 Meetily 社区版、Anarlog 免费档的现成优势，值得在记录和界面里做扎实（合并、单句改派、不重跑识别）。

### Gaps
- 各项目录音中界面的截图没有逐个看，界面描述来自 README 文字。
- 没找到对「左右并排 vs 纯笔记 vs 极简」的用户偏好量化数据或对比评测。
- 国内用户（V2EX、少数派）对这些界面的评价未找到。

## 三、谁提供了 MCP / API / CLI 让其他 AI Agent 读会议记录，怎么设计的

### Takeaway
「让 Agent 读会议」在 2026 年已成标配，设计上分三档：**只读、默认关的本机 MCP**（Yogurt、Humla、拾音）；**文件即接口**（Minutes、知了、Tingo、StenoAI 把会议写成带 frontmatter 的 Markdown，Agent 直接读盘或经 skill 读）；**全功能 Agent 面**（Minutes 34 个工具含开始/停止录音、读实时转写、加笔记；OpenWhispr 21 个工具带读写 scope；joinly 让 Agent 入会说话）。做得最细的是 Minutes：敏感会议默认排除、Agent 不能改说话人、Agent 批注只能追加不能改正文。

### Cited Findings
- **Minutes**（34 个 MCP 工具，清单由 manifest 生成）：
  - 录制控制：`start_recording / stop_recording / get_status / list_processing_jobs / start_dictation / stop_dictation`。
  - 读：`list_meetings / search_meetings / get_meeting`——**受限会议默认排除，`get_meeting` 对受限会议只返回不含内容的桩**，除非显式开启并记日志的 override。
  - 实时：`start_live_transcript / read_live_transcript`（按游标或时间窗读）、`start_copilot / stop_copilot / copilot_status / read_copilot_nudges`。
  - 跨会议记忆：`get_person_profile / research_topic / track_commitments / relationship_map / consistency_report`（标出互相矛盾的决定和过期承诺）/ `get_meeting_insights`（每条洞察带来源会议路径，放出前重新校验敏感策略，被扣下的记录报告为「部分视图」）。
  - 写入受限：`add_note` 只能给**正在进行的录音**加带时间戳的笔记，「已有会议文件不能被这个工具改」；`add_agent_annotation` 只能**追加**署名批注事件，「从不编辑会议 Markdown 或 frontmatter」，且受 `~/.minutes/agents.allow` 白名单约束；`confirm_speaker` 明确写「Agent 控制的说话人修改不可用，请用应用或人工 CLI」；`resummarize_meeting` 默认只预览且保留用户编辑。
  — [tool-map.md](https://github.com/silverstein/minutes/blob/main/.agents/skills/minutes/minutes-mcp-recall/references/tool-map.md)

## 四、会后处理：模板、分章节、跳回音频、搜索与跨会议问答，谁做得好

## 五、隐私与本地优先的可借鉴做法

### Takeaway
值得抄的做法集中在五点：**音频留存做成可选项并给出明确默认**（Humla 默认转完即删）、**临时识别结果永不落盘**（Minutes）、**敏感会议模式和受限标记贯穿到 Agent 接口**（Minutes）、**检测到会议只提议不自动录 + 首次录音前确认同意义务**（拾音、Yogurt、OpenOats、StenoAI）、**明确写出什么数据会离开本机**（OpenOats 逐个列出各供应商收到什么）。反面教材是自称本地却默认开遥测（Hyprnote 早期、screenpipe）。

### Cited Findings
- 音频是否落盘 / 保留策略：
  - Humla 默认转写和说话人识别完成即删音频；可选保留，另有「只删音频留转写」。— [Humla](https://github.com/michaelwilhelmsen/humla)
  - Granola 自述「no recording stored」。— [Granola llms.txt](https://www.granola.ai/llms.txt)
  - Speakr 有保留策略自动删除，单条录音可设豁免。— [Speakr](https://github.com/murtaza-nasir/speakr)
  - Muesli 文字经 CloudKit 私有库同步，音频只留在录音那台设备。— [Muesli](https://github.com/Muesli-HQ/muesli)
  - Tingo、JustSaid、Meetily、StenoAI 保留原始录音在本机会议目录。— [Tingo](https://github.com/tancheng33/tingo)；[JustSaid](https://github.com/bigbobro/JustSaid-public)；[Meetily](https://github.com/Zackriya-Solutions/meetily)；[StenoAI](https://github.com/stenolabs/stenoai)

- 临时内容不落盘：Minutes 实时转写的临时草稿「3 秒过期，永不写入文件、事件历史或日志」。— [features.md](https://github.com/silverstein/minutes/blob/main/docs/features.md)

### Inferences
- 委托方架构是「浏览器采音 → WebSocket → Python 后台」，与 Speakr 的「边录边流到服务器」同构，这意味着崩溃保全几乎是白送的：后台已经在持续收到 PCM，只需像 Meetily 那样**每 N 秒把收到的音频追加落盘**（或直接流式写一个不依赖文件尾的格式），界面或 Electron 崩了音频和已识别的句子都还在；再加一个 Minutes 式看门狗（一段时间没收到任何音频帧就在数字人身上用颜色/动作表现异常，而不是静默）。
- 是否留音频应做成设置里一个明确的三态：不留（Granola / Humla 默认）、留到整理稿生成后删、一直留；并提供「只删音频留文字」。这同时决定了「点回原音频」「会后精转」「说话人重聚类」三项功能是否可用，界面上应把这层依赖说清楚。
- 委托方的 `Settings.guarded` 已经是比多数竞品更细的隐私边界（按「替我开会 + 是否可谈其他项目」限定背景来源）；可补的是 Minutes 式的**按会议标记敏感度**并让 MCP 默认排除，以及「这段别记」的会中开关（JustSaid 的闲聊标记）。
- 委托方的数字人会开口说话，这一点在「告知」上反而是优势：竞品为「无机器人、别人看不见」而被质疑同意问题，数字人可以在开场用一句话声明自己在记录——把告知做成角色行为而不是弹窗。
- 「说清楚什么会离开本机」对委托方尤其要紧：会后纪要和整理稿由大模型出、干活进程会调 Claude，按 OpenOats / Minutes 的做法应在设置窗口用一两行列明「音频不出本机；这些文字会发给哪个模型」。

### Gaps
- 没有找到任何项目对「录音同意」做了自动化（例如自动在会议聊天里发告知、自动播报）的一手说明；都是提醒用户自行告知。
- 各家「本机处理」的声明没有独立审计来源；Granola「不存录音」是厂商自述。
- 国内法律语境下（个人信息保护法、录音告知）的产品做法没有查到开源项目的讨论。
- 加密落盘：只有 screenpipe 提到可选静态加密，其余项目未见说明，是否普遍不加密未核实。
